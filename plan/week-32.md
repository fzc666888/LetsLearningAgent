# 第 32 周 · 主管节点与交接上限

- **日期**：2027-06-07～2027-06-13
- **阶段**：2 · Agent 与多 Agent
- **知识层级**：L4
- **投入**：约 15 小时（Agent 约 12 小时，评测与观测约 3 小时）

## 本周目标

主管的输出是下一个角色或结束；超过四次交接必须结束。

## 完成标准

- 主管使用结构化输出，枚举只含计划、检索、写作和结束。
- 路由测试覆盖四种枚举。
- 交接计数达到 4 时忽略主管的继续请求，直接结束。
- 笔记说明上下文隔离：专家看不到无关角色的全部历史。

## 任务拆分（约 15 小时）

| 时段 | 时长 | 任务 |
|------|------|------|
| 周一 | 2.5h | 【Agent】定义主管输出模型。解析失败时默认结束，并有测试。 |
| 周二 | 2.5h | 【Agent】把主管放进图。条件边根据枚举走向三个专家或结束。 |
| 周三 | 2.5h | 【Agent】每个专家只接收任务说明和自己需要的字段。写测试证明写作节点的输入里没有计划角色的原始提示。 |
| 周四 | 2.5h | 【Agent】加入交接计数和上限。假主管一直返回检索时，测试断言第四次后结束。 |
| 周五 | 2h | 【Agent】跑一道题，记录主管每次选择。若出现重复检索，在笔记里写下次要改的提示句。 |
| 周末 | 3h | 【评测】阅读子代理文档里关于主管把专家当工具调用的说明。对照你的图，写一页：上限和上下文隔离各防止什么问题。 |

## Checklist

- [ ] 主管输出是枚举
- [ ] 四种路由有测试
- [ ] 专家输入被裁剪
- [ ] 四次交接后结束
- [ ] 对照笔记已写
