# 第 30 周 · 短时窗口与摘要记忆

- **日期**：2027-05-24～2027-05-30
- **阶段**：2 · Agent 与多 Agent
- **知识层级**：L4
- **投入**：约 15 小时（Agent 约 12 小时，评测与观测约 3 小时）

## 本周目标

消息超过阈值时先摘要再继续；同一 thread id 能接着上次的摘要说话。

## 完成标准

- 窗口函数只保留最近 n 条消息，并有单测。
- 摘要节点把被移出窗口的消息收成一段文字，放进状态。
- 检查点保存摘要。新调用使用相同 thread id 时能读到旧摘要。
- 测试证明另一个 thread id 看不到这段摘要。

## 任务拆分（约 15 小时）

| 时段 | 时长 | 任务 |
|------|------|------|
| 周一 | 2.5h | 【Agent】实现窗口裁剪。测试：不足 n 条时不变，超过时只留最后 n 条，并返回被移出的消息。 |
| 周二 | 2.5h | 【Agent】写摘要节点。测试里用假摘要函数，断言状态里出现摘要字段，原文不再全部留在消息列表。 |
| 周三 | 2.5h | 【Agent】把裁剪放进图的固定位置，位于模型节点之前。避免无限增长。 |
| 周四 | 2.5h | 【Agent】用内存检查点测试同一线程的第二次调用能看到摘要，另一线程为空。 |
| 周五 | 2h | 【Agent】用三轮以上的对话手动跑同一 thread id，确认第二轮回答提到第一轮里的一个关键词。 |
| 周末 | 3h | 【评测】重读持久化文档里短时记忆和长期存储的区别。写一页：你的摘要属于线程内记忆，要跨线程记住用户偏好还缺什么。 |

## Checklist

- [ ] 窗口裁剪有单测
- [ ] 摘要进入状态
- [ ] 同线程可恢复
- [ ] 线程之间隔离
- [ ] 笔记区分两类记忆
