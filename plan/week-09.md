# 第 9 周 · 可版本化的提示模板

- **日期**：2026-12-28～2027-01-03
- **阶段**：1 · LLM 与 RAG
- **知识层级**：L1
- **投入**：约 15 小时（应用约 11 小时，阅读约 4 小时）

## 本周目标

模板用变量渲染，结果可测试；三份模板能被代码按名字加载。

## 完成标准

- 至少三份模板：摘要、抽取、问答。每份包含身份、指令、示例槽位和上下文槽位。
- 渲染函数对同一输入永远得到同一字符串，并有测试。
- 缺变量时抛出明确错误，测试覆盖该路径。
- 笔记记下官方指南里你准备固定使用的两条写法。

## 任务拆分（约 15 小时）

| 时段 | 时长 | 任务 |
|------|------|------|
| 周一 | 2.5h | 【应用】建立 `prompts/` 目录。每份模板用 Markdown 或 YAML 保存，段落标题固定为身份、指令、示例、上下文。 |
| 周二 | 2.5h | 【应用】写渲染器：替换 `{{name}}` 这类占位符，未提供的变量要失败。为摘要模板写 3 个渲染测试。 |
| 周三 | 2.5h | 【应用】为抽取和问答各写一版模板，并准备两则你自己写的 few-shot 示例。示例内容使用短句，避免粘贴受版权保护的长文。 |
| 周四 | 2.5h | 【应用】加一个按名称加载模板的函数，名称不存在时有测试。把模板版本号写在文件顶部，修改时递增。 |
| 周五 | 2h | 【应用 1h】用渲染结果调用一次模型（密钥来自 `OPENAI_API_KEY`），把模板名、版本和是否符合格式记入笔记。【阅读 1h】阅读提示工程指南里关于消息角色和示例的部分，标出要摘录的段落。 |
| 周末 | 3h | 【阅读】读完该指南的消息格式与指令结构。用自己的话写一页：为什么上下文放在提示后部，示例怎样帮助固定格式。 |

## Checklist

- [ ] 三份模板可加载
- [ ] 渲染结果稳定
- [ ] 缺变量会失败
- [ ] 模板带版本号
- [ ] 阅读笔记已写
